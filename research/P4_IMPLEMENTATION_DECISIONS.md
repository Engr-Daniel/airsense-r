# P4 implementation decisions

Recorded 2026-10-08 before running model experiments. No final-test performance was inspected for these decisions.

- Training preprocessing uses raw rows from the dataset start through the applicable training/fold cutoff, excluding a held-out station. Fit statistics never use validation/test rows. Missing-target rows may contribute observed input values to preprocessing, but cannot train or score a supervised target.
- Numeric medians use observed raw training values. After causal imputation, population mean/standard deviation on fitting rows standardize numeric channels for MLP/GRU; zero standard deviation maps to one. XGBoost receives unscaled values. Indicators and one-hot categories are not standardized; targets remain in original units.
- All learned families receive the same 24 chronological hourly feature vectors. Tabular models flatten oldest-to-newest; sequence models retain the time dimension. Four target-calendar features are supplied separately (concatenated for tabular models and available to a GRU output head). Day-of-year phase uses zero-based day and the actual 365/366-day year length. Source timestamps are local, timezone-naive dataset times; no unsupported UTC conversion is introduced.
- Persistence predicts the last input PM2.5 after the same causal imputation policy in original units. Eligibility depends on a complete hourly history and an observed original target, not complete raw input channels. Every candidate retains the same target keys.
- Stress is applied before imputation to a separate copy of input observations, never to the immutable target series. Random/noise/whole-channel stress begins 24 hours before the first scored target and ends at the last forecast origin. Prior causal fill state is allowed; whole-channel loss means no new channel observations during that interval. Monthly outages are restricted to the test-year months as frozen in P3.
- P4 real-data verification saves structural coverage and fitted preprocessing metadata, without final-test performance or outcome-distribution exploration. Training-only diagnostics are explicitly separated from structural full-data checks.
- Config and protocol content hashes, source-tree hash, generating commit (where available), dataset checksum, parameters and environment versions identify a run. Result publication commits do not change its scientific source identity.
- Git checkpoint synchronization uses a dedicated branch with a separate checkout and synchronous, bounded retries after every saved checkpoint. This bounds unsynced work to the current unit; failures stop the runner with recoverable local files rather than silently continuing. Compact artifact files are size-limited; large arrays remain derived local files and can be deterministically reconstructed. Live Colab authentication remains runtime setup, never notebook content.
